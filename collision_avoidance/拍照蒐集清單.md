# 碰撞避障　資料蒐集清單

模型的好壞**完全**取決於拍了什麼照片。程式碼是固定的，資料不是。

---

## ⚠️ 最重要的一條

### 目標者近距離站在前方 → 標成 `free`

這是這個專案特有的，官方教學不會提。

跟隨到最後一定會靠近目標者。如果訓練資料裡沒有「人站在很近的前方」被標成安全，
模型會把被跟隨的長輩判定成障礙物，**機器人會轉頭繞開它正在跟的人**。

這個問題**沒辦法在程式裡修**，只能靠訓練資料。所以這類照片一定要拍，而且要拍多一點。

相對的代價：路人擋在正前方時，模型也會說安全。這個情境要靠距離控制與超音波處理，
已列入已知限制。

---

## 兩類的定義

| 類別 | 意思 | 資料夾 |
|---|---|---|
| `blocked` | 再往前就會撞到，或原地轉不開 | `dataset/blocked/` |
| `free` | 可以安全往前走一小段 | `dataset/free/` |

**資料夾名稱不可以改。** PyTorch 依字母排序編號，`blocked`=0、`free`=1，
推論端寫死取第 0 個當「被擋住」。改成 `danger`/`safe` 之類會讓編號反過來，
而且不會報錯——機器人會變成看到路就停、看到牆就衝。訓練腳本會擋下這種情況。

---

## 拍攝清單

目標：**每類至少 100 張，兩類數量接近**（相差不超過兩倍）。

### `free` —— 安全（建議 120 張以上）

| 場景 | 張數 | 備註 |
|---|---|---|
| 空曠走廊，各種距離與角度 | 30 | 基本款 |
| **目標者站在前方 0.3～0.8 公尺** | **25** | ⚠️ 最關鍵，不同衣服顏色都拍 |
| **目標者背對、正在走開** | **20** | 跟隨時最常見的畫面 |
| 前方有人但距離 1 公尺以上 | 15 | |
| 靠近牆面但還能轉開 | 15 | 「安全泡泡」還沒被戳破 |
| 不同地板材質（磁磚、地毯、水泥） | 15 | |

### `blocked` —— 被擋住（建議 120 張以上）

| 場景 | 張數 | 備註 |
|---|---|---|
| 正對牆面，近到轉不開 | 25 | |
| 桌腳、椅腳、櫃子 | 25 | 細長的腳最容易漏判 |
| **地上的低矮物體**（箱子、書包、石頭） | **25** | ⚠️ 相機最容易漏掉的，要多拍 |
| 樓梯邊緣、地面落差 | 15 | 拍就好，車子過不去 |
| 門檻、門關著 | 15 | |
| 牆角、死路 | 15 | 會觸發「繞不過去」判定的場景 |

## 拍攝時的注意事項

**在實際場地拍。** 映像檔內建的模型是 NVIDIA 在他們的環境訓練的，
你們走廊的地板顏色、光線都不一樣，直接用準確率通常很差。
之後要在雙溪校區戶外測試的話，那段路也要另外拍一批。

**光線要變化。** 走廊燈下、靠窗、陰天、開燈關燈都拍一些。
這是實測時最常見的失效原因。

**角度要變化。** 同一個障礙物從正面、斜 30 度、斜 60 度各拍幾張。

**判斷標準是「安全泡泡」。** 問自己：*機器人在這個位置原地轉一圈，會撞到東西嗎？*
會就是 `blocked`。注意 JetBot 是繞兩輪中心轉，不是車體中心。
**猶豫的時候就標 `blocked`**，寧可多繞路也不要撞上去。

## 操作流程

### 1. 在 JetBot 上蒐集

開啟 `collision_avoidance/data_collection.ipynb`，照官方流程按按鈕存圖。
畫面上會顯示兩類各存了幾張，**邊拍邊看，讓兩邊數量接近**。

拍完執行最後一格打包：

```
!zip -r -q dataset.zip dataset
```

然後在 Jupyter 檔案瀏覽器右鍵下載 `dataset.zip` 到筆電。

### 2. 在筆電訓練

解壓縮到 `程式碼/collision_avoidance/dataset/`，確認結構是：

```
dataset/
├─ blocked/   *.jpg
└─ free/      *.jpg
```

然後在 Windows PowerShell 執行：

```bash
python train_collision.py --data dataset
```

預設用 ResNet18、30 個 epoch。你的筆電是 CPU 訓練，幾百張圖大約十幾到三十分鐘。
第一次執行會下載約 45MB 的預訓練權重，要連網路。

### 3. 看結果

訓練完會印出混淆矩陣：

```
              判成 blocked   判成 free
  實際 blocked       48           2      ← 這個 2 是「漏報」
  實際 free           3          47      ← 這個 3 是「誤報」
```

**兩種錯誤的嚴重程度不一樣：**

- **漏報**（實際被擋住卻判成安全）→ **會撞上去**，危險
- **誤報**（實際安全卻判成被擋住）→ 多繞路，不危險

準確率一樣是 95%，漏報多的那個模型比較危險。
**漏報不是零的話，回去補拍那些會漏判的場景再訓練一次。**

### 4. 放回車上

把 `best_model_resnet18.pth` 複製到 JetBot 的
`~/Notebooks/collision_avoidance/` 底下。

## 訓練腳本比官方多做的事

| 項目 | 官方 | 這支 |
|---|---|---|
| 類別編號 | 不檢查 | **強制檢查**，對不上就停止 |
| 測試集大小 | 寫死 50 張 | 比例分割（20%） |
| 分割方式 | 隨機 | **分層抽樣**，確保測試集兩類都有 |
| 資料不到 51 張 | **崩潰** | 正常運作 |
| 類別不平衡 | 不檢查 | 相差超過兩倍會警告 |
| 評估 | 只有準確率 | **混淆矩陣**，區分漏報與誤報 |
| 模型架構 | AlexNet | ResNet18（可用 `--arch alexnet` 切回） |
| 類別對照表 | 不存 | 存成 `_meta.json` |

## 為什麼建議 ResNet18 而不是官方的 AlexNet

| | AlexNet | ResNet18 |
|---|---|---|
| 參數量 | 6100 萬 | **1100 萬** |
| 推論速度 | 慢 | **快** |
| TensorRT 路徑 | 無現成範例 | bundle 裡已有 `live_demo_resnet18_build_trt.ipynb` |

FPS 是目前最大的風險（構想書要求 ≥15），而跟隨的每一幀都要跑這個模型。
同樣的資料、同樣的流程，換成 ResNet18 是免費的改善。
