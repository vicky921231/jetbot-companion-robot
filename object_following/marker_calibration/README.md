# 標記顏色校正

`marker.py` 的 HSV 門檻要量出來，不能猜。這個資料夾就是量的流程。

**這一步等價於神經網路的「訓練」**，只是參數從 1100 萬個變成 6 個，
不用 GPU、不用標框，十分鐘做完。

---

## 為什麼非做不可

`marker.py` 裡目前的數字是**估計的起點**，不是實測值。同一張色紙在日光燈下、
在窗邊、在走廊陰影裡，HSV 讀數會差很多。沒校正就上車，最可能的兩種症狀：

| 症狀 | 原因 |
|---|---|
| 完全鎖不上，一直停在 `waiting` | 門檻太嚴，標記抓不到 |
| 沒貼標記的人也鎖得上 | 門檻太鬆，抓到的是褲子或地板 |

兩種都不會報錯，只會「行為怪怪的」。

---

## 流程

### ① 在 JetBot 上拍照

開 `capture_samples.ipynb`。

**拍之前確認兩件事：**

- **攝影機角度已經固定。** 角度一改，全部重來
- **解析度是 300×300**（與 `live_demo_following_sm.ipynb` 一致）。標記偵測跑在
  原始相機畫面上；避障模型的 224×168 是 `preprocess()` 裡另外 resize 的，與這裡無關

兩種照片分開拍：

| 前綴 | 距離 | 張數 | 用途 |
|---|---|---|---|
| `close` | 約 0.3 m 特寫 | 5~8 | 量顏色 |
| `0.5m` `0.8m` `1.5m` `2.0m` | 站立全身 | 各 3~4 | 驗證距離 |

特寫要涵蓋不同光線（一般室內 / 靠窗 / 陰影），不然門檻只在拍攝當下那個亮度成立。
距離照要包含**走路中途兩腿交錯的那一瞬間** —— 那是最容易失敗的狀況。

霧面和亮面都買了的話各拍一輪，前綴加 `matte` / `gloss`，分開跑就能直接比過曝。

拍完把 `samples/` 整個複製回筆電。

### ② 在筆電上量顏色

```bash
python analyze_marker.py samples --pick
```

只挑 `close` 開頭的特寫來框。每張圖會開兩次視窗：先框桃紅區，再框第二色區。
畫面已經放大 6 倍，框「緊」一點，不要框到旁邊的褲子或地板。

跑完會印出兩行可以直接貼進 `marker.py` 的門檻，例如：

```
    pink_ranges = [((161, 168, 92), (172, 255, 255))]
    second_ranges = [((26, 190, 104), (39, 255, 255))]
```

同時會報告**過曝比例**。超過 5% 就代表材質的鏡面高光已經把顏色打成白色，
那些像素的色相不可信 —— 換霧面材質，或把相機的 exposure / gain 調低。

### ③ 貼回 marker.py

打開 `../marker.py`，找到 `MarkerConfig`，用實測值取代原本的估計值。

### ④ 驗證距離

```bash
python analyze_marker.py samples --check --save-masks
```

會印出每張圖抓到幾個像素、雙色驗證在哪個距離開始失效，例如：

```
雙色驗證成功的最遠距離：1.00 m
只認桃紅成功的最遠距離：2.00 m
```

然後把 `marker.py` 的 `dual_color_min_bbox_h` 設成「雙色最遠距離」對應的框高
（框高 0.30 約 1.5 m、0.45 約 1.0 m、0.55 約 0.8 m）。

`--save-masks` 會把偵測框疊在原圖上存到 `samples/check_out/`，用眼睛確認
框有沒有落在標記上，而不是落在別的東西上。

### ⑤ 回歸測試

```bash
python ../test_marker.py
```

改完門檻跑一次，確認沒把邏輯改壞。這支測的是**邏輯**不是門檻，
所以任何門檻值都應該通過。

## 上車之後

`live_demo_following_sm.ipynb` 的畫面左上角會多顯示 `M<數字>`，
數字是這一幀抓到的桃紅像素數；同時標記位置會畫一個**洋紅色細框**。

現場調整就看這兩個：

| 看到什麼 | 意思 | 怎麼辦 |
|---|---|---|
| 洋紅框穩定跟著腿 | 正常 | 不用動 |
| 框一直閃爍 | 門檻太嚴 | 把 S / V 下限調低一點 |
| 框跑到褲子或地板上 | 門檻太鬆 | 把 H 範圍縮窄、S 下限調高 |
| `M` 完全不出現 | 沒抓到 | 先確認解析度和光線與校正時一致 |
